# 多信号画像实验

分支：`feat/multimodal-recommendation`。这是供验证的实现，尚未合并或发布。

## 当前行为

- 画像支持任意兴趣主题、自然语言描述、排除主题、按 UID 学习的 UP 主偏好，以及收藏封面的相似度。摄影、旅行、游戏、软件等不经过音乐词典才能参与推荐。
- 标题或标签匹配构成基础候选；作者偏好只能调整已匹配视频的排序。排除主题和屏蔽 UP 主优先。可单独忽略作者的加分，或完全屏蔽作者。
- 首次使用不下载模型。本地 AI 在画像详情中按需下载、校验 SHA-256 后开启，可暂停、删除或清理分析缓存。无模型、离线、设备繁忙、推理失败时继续使用标题和标签。
- AI 只使用已完成的本地分析结果，不阻塞取流，也不因分析完成重新排列已展示卡片。首次遇到的视频可能尚未有向量，随后取流可复用缓存。
- 当前 `renderer/profile-calibration.json` 为空：语义和封面只辅助排序，不能独立放行新主题的视频。尚无人工独立标注的推荐测试集，不宣称已达到 95% 精度。
- 日推仍通过音乐目录匹配 B 站歌曲，保留现有的至少 15 首目标与七天去重；没有可识别音乐兴趣的画像会提示选择音乐画像，不把一般兴趣自动当成歌手名。

## 画像隔离与同步

首页和发现页使用各自现有的同步文档，各有一个近期画像。行为携带 `profileId`，喜欢和歌单视频还携带 `recommendationScope`。播放开始时捕获画像 ID；稍后切换画像不会改变这次播放的归属。未标记的历史行为兼容归入原来的近期画像。

行为记录立即保存；派生兴趣、作者权重和封面样本仍每 15 分钟批量更新，也可手动更新。曝光和候选不成为封面正样本；封面样本来自明确喜欢/收藏。自建画像的行为不会加入其他自建画像或近期画像。

同步包含描述、排除规则、作者规则、样本引用与时间戳，继续使用现有局域网和云同步管道。缺少扩展字段的旧端不会在合并时删除新端字段。作者恢复、清空描述、移除样本和重置封面学习都有显式记录。模型文件、图片、向量缓存和本机模型开关不进入同步文档。桌面仍只使用主画像，不参与发现页学习。

## 模型与运行时

`renderer/profile-models.json` 固定转换版本、文件长度、SHA-256、来源与预处理说明：

| 用途 | 模型 | 下载量 | 输入 / 输出 |
| --- | --- | --- | --- |
| 标题语义 | BAAI/bge-small-zh-v1.5，Xenova 量化 ONNX 转换 | 约 23.3 MiB，含 tokenizer | 大小写敏感 WordPiece，最多 128 token；CLS，512 维，L2 归一化 |
| 封面相似 | MobileCLIP2-S0，felixhrdyn 图像编码器量化转换 | 约 11.3 MiB | 居中裁切、256×256 RGB、CLIP 标准化；512 维，L2 归一化 |

文本模型：[原模型及 MIT 许可](https://huggingface.co/BAAI/bge-small-zh-v1.5)、[转换版本](https://huggingface.co/Xenova/bge-small-zh-v1.5/tree/75c43b069aac4d136ba6bc1122f995fedcfd2781)。

图像模型：[Apple 原模型](https://huggingface.co/apple/MobileCLIP2-S0)、[Apple 模型许可](https://github.com/apple-aiml-research/ml-mobileclip/blob/main/LICENSE_MODELS)、[转换版本](https://huggingface.co/felixhrdyn/mobileclip2-s0-onnx/tree/99ca0cde6c76c0c56fcfeace07eb3a340ba17fc0)。转换仓库的标签不能替代 Apple 原模型许可。此处只进行图像与图像比较，不把中文描述送入英文 CLIP 文本编码器。

桌面通过 Electron worker thread 使用 ONNX Runtime Node 与 sharp；Android/iOS 通过本地 Expo 模块在后台串行队列使用 ONNX Runtime 1.24.3。单会话、单推理线程；切换模型释放前一个会话。任务上限 200，向量缓存上限约 2000（磁盘按分钟整理）。移动端磁盘清理在原生队列中执行。

点击导航、播放缓冲、切到后台时让出分析；移动端低电量模式、热状态和内存压力限制分析。任务之间安排间隔，封面使用 CDN 缩略图及图片磁盘缓存。已经开始的一次推理不会被强行中断。实际耗电、内存峰值和播放稳定性仍需真机验证。

## 独立放行的验证门槛

通过验证后，封面独立候选仍必须满足：至少 5 个有效正样本、至少 2 个 UP 主、至少 2 个相似邻居、用户未禁用视觉推荐且未命中排除规则；每批输出的累计比例不超过 20%。同一封面 URL 不重复计算样本。重置和删除样本生效后不再参与相似度计算。

校准工具：

```bash
node scripts/calibrate-profile.cjs /path/to/labeled-scores.json /path/to/report.json
```

输入格式：

```json
{
  "kind": "text",
  "reviewedBy": "独立审核人",
  "samples": [
    { "id": "profileA:BVexample", "group": "same-content-family", "split": "test", "score": 0.81, "label": true }
  ]
}
```

分数必须由本版本模型和生产预处理计算，标签必须由人根据画像与视频内容独立判定。至少 200 条独立样本；测试部分至少 100 条、20 条正例与 30 条负例；校准部分至少 20 条正例及 20 条负例。近重复内容/同一视频的分组不能跨校准和测试集。包含无标签、误导标题、同名 UP、软件与视觉主题混淆、重复封面等困难负例，并覆盖非音乐兴趣。

工具只在校准集选择阈值，测试集不参与选阈值；测试集必须有至少 20 个放行样本且放行精度至少 95%。拒绝重用 ID、跨集合分组和不足样本。报告保存数据集哈希、模型 ID、阈值、精度、召回率和计数。

审核通过后才将报告放入 `renderer/profile-calibration.json` 对应的 `text` / `image` 字段，重新构建。脚本不会自动启用开关。更换模型或预处理时应更新模型 ID、清理旧向量，并重新校准。当前还未完成社区转换与 Apple 原始权重的完整数值一致性验证，因此图像独立放行保持关闭。

## 本轮验证

- 完整 Node 回归：317 项通过，包括画像隔离、旧端字段兼容、作者排除、视觉配额、定时学习和现有播放/同步测试。
- 桌面 Web 生产构建成功；经典脚本初始化通过。
- Android Kotlin 与 iOS Swift 原生分析模块编译成功。
- Expo 完整 iOS、Android Hermes 包导出成功。
- 固定 ONNX 文件实际下载并校验，桌面文本与图像会话及 512 维输出已验证。9 组中文、英文、大小写、标点和截断输入与官方 tokenizer 输出一致。

没有进行手机安装、截图测试、商店发布或主分支合并。后续真机重点验证：开启/关闭模型前后播放与导航是否流畅；切换账号及首页/发现页画像不串学习；取消下载和低电量降级；两端同步后排除/恢复/移除样本的一致性；每日歌曲七天内不重复。Windows 原生依赖的完整打包还需要在 Windows 上验证。
