# 移动端点击响应与后台计算隔离

本轮覆盖 iOS、安卓。未做截图、模拟点击或自动启动应用；真实冷启动和触控体验由用户验证。

## 找到的阻塞路径

- 云同步的 `seal` / `unseal` 原来同步执行 JSON、gzip、AES-GCM、SHA-256。原生视频编码虽然已有后台队列，编码前后的这些工作仍占用 RN JS 线程。
- LAN 同步反复在 JS 中校验全库、三方合并、序列化和计算 MD5；云同步也有相同的全库处理。
- 画像提交重新归一化、计算兴趣并发布全局状态；导航和我的页面原来订阅完整 PlayerContext，收到无关状态也重新渲染。
- 首页、发现页的 blur 回调直接触发请求取消及其监听回调；发现页进入后马上配置播放器和预加载实例。

## 实施

- 使用现有 Worklets 创建独立 `biu-data` 运行环境。`build-compute.cjs` 用构建依赖 esbuild 打包原共享算法，Metro 启动及正式构建自动生成自包含 worklet；由 Worklets 加载编译产物，没有网络下载代码。
- 全库校验、合并、MD5/SHA-256、JSON、画像归一化、每日推荐筛选、云快照压缩/解压/加解密转到工作线程。网络与原生 I/O 继续异步运行。
- 工作线程入口复制参数时每约 4ms 让出 JS。只传递副本，避免 Worklets 冻结或缓存页面正在使用、可能继续补充元数据的对象；保留重复引用，防止重复复制。
- 工作线程返回后重新检查账号、取消状态和收藏数据是否已变化，再提交结果。歌单、收藏和云状态保留写入顺序。
- 画像导出复用已提交的规范快照；连续推荐观察合并提交。PlayerContext 支持按字段订阅，底部导航、首页、我的页面不再订阅无关的画像和播放状态。
- 离页先使旧结果失效，再异步取消传输。首页恢复请求、发现页进入后的播放器准备让出导航提交；发现页内部正常换卡不增加这段等待。旧清理不会取消新请求。

修改共享算法后，开发环境需要重新启动 Metro，或运行 `node mobile-rn/scripts/build-compute.cjs` 更新生成文件。正式构建及测试会自动生成。

## 验证

279 项测试通过（含 Hermes 兼容回归），Android arm64 Release 和 iOS Simulator Release 构建通过。

新增验证包含：真正独立的 Node 工作线程执行大库合并时调用线程继续处理定时事件；Worklets Babel 编译后的工厂闭包为空，在没有 React、Metro、浏览器构造器的独立 VM 中正常执行；Python 云快照解密、Unicode、错误密钥、同步摘要、删除语义、主画像与发现画像隔离；参数不冻结原状态；无关画像更新不重绘导航和音乐库订阅者。

### Hermes 兼容回归修复

上一版 Node 验证没有覆盖 Hermes 的源码求值路径。使用项目 Pods 自带的 Hermes 引擎复现：esbuild 导出辅助函数中的 `for (let key ...)` 闭包在该路径读取了最后一个 key，导致 `Buffer` 导出变成其他值，工厂在 `Buffer.from` 初始化时报 `undefined is not a function`。这同时阻断发现页、画像读取和云配置 JSON 解析。

生成阶段使用已有 Babel block-scoping 转换保留每次循环的闭包绑定，在 Worklets 捕获源码前完成处理。新增测试以 Expo 正式 iOS、安卓配置编译工厂，再交给实际 Hermes 引擎执行，覆盖配置、画像、摘要和云加解密。此引擎测试在 macOS 且已安装 iOS Pods 时运行，其他环境明确跳过。它仍不代替实机触控测试。

云配置仅在 JSON 语法或必需字段无效时提示损坏；运行环境和 I/O 异常提示读取失败，保留原配置及密钥，允许重试。

运行 `node mobile-rn/scripts/benchmark-responsiveness.cjs` 可重做算法对比。一次 macOS / Node v26.5.0、3000 首数据的结果如下，包含工作线程参数和结果传递：

| 相同合并、摘要、加密任务 | 原同步执行 | 独立线程执行 |
| --- | ---: | ---: |
| 总耗时 | 1964ms | 2552ms |
| 调用线程最长事件循环延迟 | 1966.1ms | 14.7ms |

这是合成数据的算法对比，不是手机点击延迟、帧率或 Worklets 跨线程成本的测量。它说明移出计算能释放调用线程，并不承诺计算总耗时变短。

## 实机诊断与导航决定

`[BiuTiming]` 日志记录超过 100ms 的阶段耗时；内存仅保留最近 120 条元数据，无视频标题、账号、音乐库内容或密钥。阶段包括工作线程初始化、参数准备、派发、工作线程计算和总等待时间；前台事件循环以 250ms 间隔检测停顿。底部导航记录 JS 接收点击到选中状态提交、下一次帧回调的时间。

导航计时起点是 JS 收到有效点击，不等于手指触屏时刻；下一次帧回调也不等于真实显示器完成呈现。后台任务总耗时不能当作 JS 阻塞时长，需结合 `event-loop` / `dispatch` 与导航日志。

当前保留原生 native-stack 转场及现有底部导航，不另建一套原生路由状态。已证实并处理的主要问题是 JS 计算和订阅范围。若实机日志显示事件循环稳定、工作派发无长停顿，但底部切换仍显著迟滞，再评估原生底部导航；若派发或结果回传过慢，优先继续缩小数据传递，避免只改变按钮外观而内容仍延迟。
